## Часть 1. Технические решения

Бриф требовал согласовать их до кода. Поскольку решения делегированы мне, каждое приведено с альтернативой, обоснованием и **ценой отката** — ни одно не является необратимым.

### 1.1. CSS: собственный слой с токенами, не Tailwind

**Решение: оставляем собственный CSS с токенами (уже построен на Этапе 2). Tailwind и django-tailwind не вводим.**

| | Собственный CSS + токены | Tailwind + django-tailwind |
|---|---|---|
| Шаг сборки | Не нужен (`collectstatic` + WhiteNoise) | Нужен Node в Docker и на Vercel |
| Миграция | Постранично, два слоя сосуществуют | Разом либо долгое двоевластие |
| Уже сделано | ~1200 строк слоя `ui-`, проверены | Ноль |
| Тёмная тема | Работает через токены | Переписывать под `dark:` |
| Размер | ~74 КБ сырых, gzip ~15 КБ | Меньше при purge, но плюс сборка |

Решающий довод — не вкусовой: **в проекте сейчас нет ни одного шага сборки фронтенда**, а деплой идёт и в Docker, и на Vercel. Введение Node-цепочки ради утилитарных классов увеличит поверхность отказа деплоя ради выигрыша, который у нас уже получен токенами. Плюс Tailwind обесценил бы работу Этапа 2 целиком.

**Именование — не строгий BEM**, а то, что уже реализовано и проверено: префикс `ui-`, элемент через `__`, модификатор через `--`, состояние через `.is-*` / атрибут (`[disabled]`, `[aria-selected]`). Строгий BEM с его `block__element--modifier` на каждом узле даёт длинные имена без выигрыша при нашем размере проекта.

*Откат:* установить django-tailwind и переписать слой. Дорого — решение стоит считать принятым надолго.

### 1.2. Интерактив: htmx (самохостинг) + минимум vanilla, без Alpine

**Решение: htmx оставляем, но переносим с CDN в свою статику и начинаем реально использовать. Alpine.js не добавляем.**

Сейчас htmx грузится с `unpkg.com` на каждой странице и **не используется ни разу** (0 атрибутов `hx-*`). Это худший из возможных вариантов: платим весом и внешним доменом в критическом пути, не получая ничего.

Три возможности:

1. **Удалить htmx полностью.** Экономит ~17 КБ gzip и внешний домен. Но тогда замена drag&drop на кнопки «вверх/вниз» (обязательство WCAG 2.5.7) даёт полную перезагрузку страницы на каждое нажатие — в конструкторе с десятком блоков это невыносимо.
2. **Оставить с CDN.** Внешний домен в критическом пути — это отказ стороннего сервиса, роняющий интерактив, и утечка адресов пользователей к третьей стороне.
3. **Самохостинг + применение.** ✅ Выбрано.

Внешний домен убирается, вес остаётся, но начинает окупаться. Применения намечены точечно: переупорядочивание блоков и тем, удаление блока, отметка «выполнено», отправка сообщения, пагинация списков.

**Alpine.js не добавляем.** Клиентского состояния у нас почти нет, а то, что есть, закрывается нативно: `<details>` для аккордеонов и меню, `<dialog>` для модалок (даёт ловушку фокуса и Escape бесплатно — проверено на Этапе 2). Alpine — это ещё ~15 КБ и второй способ описывать поведение рядом с htmx. Vanilla-модули по одному файлу на ответственность остаются для редактора вопросов по изображению и WebSocket-чата.

*Откат:* добавить `<script>` — минуты.

### 1.3. Переиспользование: `{% include %}` + `inclusion_tag`, без django-components

**Решение: партиалы через `{% include %}`; `inclusion_tag` только там, где компоненту нужно вычислить контекст.**

`django-components` — новая зависимость и третья парадигма шаблонов в проекте, где сейчас всего 3 включения на 32 шаблона. Выигрыш не окупает обучение и зависимость.

Правила:
- партиалы живут в `templates/components/`, по файлу на компонент;
- каждый партиал начинается с комментария, перечисляющего ожидаемые параметры;
- передача только через `{% include ... with x=y %}`, без опоры на «что-то придёт из внешнего контекста»;
- `inclusion_tag` — когда нужно посчитать (например, сегменты прогресса из списка блоков), а не просто подставить.

### 1.4. Формы: свой шаблон поля, не crispy-forms

**Решение: единый партиал поля + постепенный перевод ручных форм на Django Forms. crispy-forms не вводим.**

Обоснование опирается на замер, а не на предпочтение:

| Категория | Шаблонов | Форм |
|---|---:|---:|
| Используют Django Form | 5 | 6 |
| Ручной HTML с полями ввода | 5 | 22 |
| Ручной HTML без полей (только кнопка + hidden) | 6 | 6 |

**crispy-forms улучшил бы только 6 форм из 34** — те, что уже являются Django Forms. Остальные 22 формы с полями ввода написаны как `<input name="section_title">` и читаются во view через `request.POST.get(...)`; для crispy их не существует. Ставить зависимость ради шестой части работы — неверный размен.

Что делаем вместо:

1. `templates/components/field.html` — один партиал поля: метка, виджет, подсказка, ошибка, `aria-describedby`, `aria-invalid`. Работает и с Django-полем, и с ручной разметкой.
2. `templates/components/form_errors.html` — сводка ошибок GOV.UK.
3. Формы **без полей ввода** (записаться, отметить выполненным, прочитать все) не нуждаются ни в Django Form, ни в партиале поля — им нужна только кнопка нужного класса. Это 6 форм, закрываются в один проход.
4. Формы **с полями** переводятся на Django Forms постепенно, по мере миграции своей страницы. Приоритет там, где отображение ошибок важнее всего: создание курса, создание теста, добавление пользователя.

**Это меняет внутренности view** (появляется `form = XForm(request.POST)` вместо `request.POST.get`). Имена view, URL и контекстные переменные не меняются. Каждый такой случай отмечен в плане отдельно.

### 1.5. Статика: без сборщика, кеш-бастинг починить

**Минификация — не вводим.** CSS ~74 КБ сырых, WhiteNoise отдаёт gzip (~15 КБ). Отдельный минификатор потребовал бы либо Node, либо django-compressor — то же увеличение поверхности отказа деплоя ради 2–3 КБ.

**Кеш-бастинг — сейчас делается дважды и это надо чинить.** WhiteNoise уже даёт хеш в имени файла (`app.180141bf.css`), а поверх этого `base.html` добавляет `?v={{ static_asset_version }}`, где context processor на **каждый запрос** обходит диск через `rglob("*.css")`. Решение: оставить `?v=` только при `DEBUG` (в разработке манифест не используется, и без него браузер кеширует правку CSS), в проде вернуть пустую строку и не трогать диск.

**Критический CSS — не вводим.** Сейчас 10 тегов `<link>`. Инлайнить критическую часть без шага сборки означает поддерживать её вручную, что гарантированно разойдётся с реальностью. Правильный путь у нас другой: число файлов сократится само, когда легаси-слой будет удалён (Этап 4.14). Под HTTP/2 несколько параллельных файлов дешевле, чем ручной критический CSS, который врёт.

### 1.6. Тема Django Admin — вне скоупа

`ADMIN_URL` в проде пуст по умолчанию, админка доступна только при явной настройке приватного адреса. Ставить django-unfold или jazzmin ради интерфейса, которым, судя по конфигурации, не пользуются, — расход без адресата.

## Часть 2. План по этапам

Каждый этап — один коммит, самостоятельно ревьюится, мёржится и деплоится. Порядок: фундамент → частые страницы → редкие → уборка.

Обозначения: **[V]** нужны изменения во view (описаны явно), **[!]** закрывает баг из аудита, **[A11Y]** закрывает нарушение доступности.

### Блок 0 — фундамент (блокирует всё остальное)

#### 4.0. base.html, навигация, сообщения, страницы ошибок [!] [A11Y]
`templates/base.html`, `templates/components/alert.html`, `templates/errors/*.html`

- Сообщения рендерятся по `message.tags` в четыре уровня; `role="alert"` для ошибок вместо `status` для всех **[!]** п. 7.3
- `components/alert.html` перестаёт быть самостоятельным ответом: получает `{% extends %}`, шапку и путь назад **[!]** п. 7.1 — сейчас при истёкшей ссылке пользователь видит голый абзац без навигации

- `scroll-padding-top` под липкую шапку — WCAG 2.4.11 **[A11Y]**
- Область тостов объявляется в разметке
- Страницы ошибок 400/403/404/500 на `.ui-empty`

**[V]** `config/context_processors.py`: `static_asset_version` возвращает пустую строку вне DEBUG.

## Часть 3. Критерий приёмки страницы

Страница считается готовой только при выполнении **всех** пунктов. Список висит в шаблоне описания коммита.

**Раскладка**
- [ ] 360 / 768 / 1280 / 1920 без горизонтального переполнения (проверять `scrollWidth === innerWidth`, а не на глаз)
- [ ] Тёмная и светлая тема
- [ ] Плотный режим — для страниц Блока 3

**Состояния**
- [ ] Пустое состояние с действием
- [ ] Ошибка: сводка вверху + сообщение у поля, тексты совпадают дословно
- [ ] Загрузка по порогам: <1с ничего, 1–10с спиннер, >10с прогресс
- [ ] Все интерактивные элементы имеют hover / focus-visible / disabled

**Доступность**
- [ ] Проход по Tab в логичном порядке, ничего не теряется
- [ ] Один `<h1>`, уровни заголовков не перескакивают
- [ ] Цель нажатия ≥ 24×24px (WCAG 2.5.8)
- [ ] Элемент в фокусе не скрыт липкой шапкой (WCAG 2.4.11)
- [ ] Цвет не единственный носитель смысла
- [ ] `alt` у изображений, `aria-label` у иконочных кнопок

**Код**
- [ ] Ни одного `style=`, кроме передачи данного через кастомное свойство
- [ ] Ни одного `!important`
- [ ] Ни одного хардкоженного цвета или размера
- [ ] Мёртвый CSS этой страницы удалён в этом же коммите
- [ ] Тексты сохранены дословно

**Проверки**
- [ ] `manage.py check`, `pytest`, `ruff check`, `ruff format --check`
- [ ] `collectstatic` при добавлении статических файлов
- [ ] Страница открыта в браузере, консоль чиста

**Отдельно про объёмы данных.** Вопрос из аудита остаётся без ответа: сколько студентов в крупнейшей организации.
