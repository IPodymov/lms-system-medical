## Первое, что сделать в новой сессии

```bash
cd /путь/к/lms-system-medical
git switch redesign/stage-4.6-notifications

# База локальная, в git её нет — при чистом клоне нужно поднять заново
DJANGO_USE_SQLITE=1 .venv/bin/python manage.py migrate
DJANGO_USE_SQLITE=1 .venv/bin/python manage.py seed_demo   # пароль всех: demo12345

# Обязательно: без этого падают ВСЕ тесты (WHITENOISE_MANIFEST_STRICT)
DJANGO_USE_SQLITE=1 .venv/bin/python manage.py collectstatic --noinput

DJANGO_USE_SQLITE=1 .venv/bin/python -m pytest -q     # ожидается 114 passed
```

Прочитать перед правками: скилы `.claude/skills/design/SKILL.md` и
`.claude/skills/frontend-traps/SKILL.md`. Второй — список ловушек, каждая
из которых уже стоила отладки в этом проекте.

Локальный просмотр:

```bash
# Именно DEBUG=1: settings.py сравнивает строку с "1", поэтому DEBUG=True
# означает DEBUG=False — Django включает кеширующий загрузчик шаблонов, и
# правки шаблонов не видны до перезапуска сервера
DJANGO_USE_SQLITE=1 DEBUG=1 .venv/bin/python manage.py runserver 8000
```

Каталог компонентов: `http://127.0.0.1:8000/styleguide/` — нужен пользователь
с `is_staff` (в демо-данных это `admin@demo.local`).

## Что нельзя забыть на каждом этапе

1. **Сверить тексты машинно, а не глазами.** Правило заказчика — существующие
   строки не теряются. Один раз меня на этом поймал существующий тест:

   ```bash
   git show HEAD:templates/путь.html | grep -oE '>[^<>{%]{3,}<' \
     | sed 's/^>//;s/<$//' | sort -u
   ```

   Каждую строку из вывода найти в новом шаблоне.

2. **`collectstatic` после добавления любого файла в `static/`.**

3. **Удалить мёртвый CSS в том же коммите.** Проверка, что класс больше
   нигде не нужен:

   ```bash
   grep -rhoE 'class="[^"]*"' templates | sed 's/class="//;s/"//' \
     | tr ' ' '\n' | grep -x "имя-класса" | wc -l
   ```

   Ноль — можно удалять. Осторожно с составными селекторами: удалять правило
   можно, только если **все** его части держатся на мёртвых классах.

4. **Открыть страницу в браузере.** Три дефекта этого редизайна нашлись
   только глазами и ни один — тестами: сплющенная иконка, растянутая кнопка,
   legend поверх рамки.

5. **Прогнать** `manage.py check`, `pytest`, `ruff check`, `ruff format --check`.

## Открытые вопросы к заказчику

1. **Объёмы данных.** Сколько студентов в крупнейшей организации? Пока ответа
   нет, пагинация везде вынесена в отдельные коммиты и не блокирует
   визуальную миграцию. Если счёт идёт на сотни, `<select name="user_id">`
   в панели управления (все студенты разом, без поиска) — функциональная
   проблема, и её приоритет выше редизайна.

2. **Удаления `.agents/.skills/*`** висят в рабочем дереве как
   незакоммиченные. Их сделал не я. `git restore .agents/` вернёт файлы,
   `git add -A .agents/` зафиксирует удаление.

## Самое рискованное впереди

**Этап 4.12, конструктор курса** (`templates/courses/edit.html`, 13.7 КБ,
10 форм, 35 строк инлайнового JS).

Там обязательство по доступности: WCAG 2.5.7 требует альтернативу
перетаскиванию одним указателем — кнопки «вверх / вниз» рядом с каждой темой
и блоком. Сейчас переупорядочить программу без мыши невозможно.

**Drag&drop при этом сохраняется и работает параллельно.** Это прямое
применение антипаттерна А6 из `01-references.md`: Open edX удалил боковую
навигацию «на время» и возвращал её годами. Не удалять работающее.

Закладывать отдельный проход ручного тестирования.
