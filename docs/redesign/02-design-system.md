| Вопрос | Решение | Обоснование | Цена отката |

## 2. Токены

### 2.1. Цвет

Основной принцип — **полный набор из четырёх токенов на каждый семантический цвет**:

```
--color-success            сплошной: текст и иконки на обычной поверхности
--color-success-surface    подложка плашки
--color-on-success-surface текст на этой подложке
--color-success-border     граница подложки
```

До этого этапа пара «поверхность → текст на ней» существовала только у primary. Из-за этого любая попытка сделать зелёную плашку успеха требовала угадывать цвет текста — и, скорее всего, промахнуться мимо 4.5:1.

**Поверхности** идут от дальней к ближней: `--color-background` → `--color-surface` → `--color-surface-raised` → `--color-surface-overlay`. `--color-surface-sunken` — утопленная (поля ввода в светлой теме, фон площадок).

**Тёмная тема** задаётся дважды: в `@media (prefers-color-scheme: dark)` для `:root:not([data-theme="light"])` и в `:root[data-theme="dark"]`. Дублирование сознательное: `light-dark()` убрал бы повтор, но при отсутствии поддержки оставил бы страницу полностью без цветов, а не с одной некорректной границей. Оба блока обязаны совпадать значение в значение — это единственное место в системе, где нужна ручная синхронизация.

**Псевдонимы для легаси.** В конце светлого блока — семь токенов (`--color-surface-soft`, `--color-accent-text`, `--shadow-card` и др.), на которые ссылается прежний CSS. Они позволяют не переписывать 3800 строк разом. По мере миграции страниц использования уходят, после чего блок удаляется целиком. Новый код их использовать не должен.

### 2.3. Отступы

База 8px, имя токена равно значению в пикселях: `--space-16` — это 16px, сверяться с таблицей не нужно.

```
2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80
```

Шаги 2/4/6 нужны бейджам, счётчикам и компактным элементам, где 8px — уже слишком много. До этого этапа шкалы не было вовсе: по CSS россыпью встречались 5, 7, 9, 13, 22, 26 px.

### 2.4. Типографика

В `rem`, чтобы уважать настройку размера шрифта в браузере. База **16px** (было 15px хардкодом) — это минимум, при котором мобильный Safari не масштабирует страницу при фокусе на поле ввода.

| Токен | Размер | Назначение |
|---|---|---|
| `--text-38` / `--text-30` | 38 / 30 | Заголовок страницы, h1 |
| `--text-24` / `--text-20` / `--text-18` | 24 / 20 / 18 | h2, h3, h4 |
| `--text-16` | 16 | Основной текст |
| `--text-14` | 14 | Метки полей, плотные таблицы |
| `--text-13` / `--text-12` / `--text-11` | 13 / 12 / 11 | Подписи, заголовки колонок, счётчики |

Вес: 400 / 500 / 600 / 700. Межстрочный: 1.2 (заголовки) / 1.35 / 1.55 (основной текст).

`--measure: 68ch` ограничивает длину строки, но применяется **адресно** через `.ui-prose`, а не глобально ко всем `<p>`. Прежнее правило `p { max-width: 75ch }` било по абзацам внутри карточек и ячеек таблицы, где ограничение вредно.

### 2.5. Точки останова

Пять значений, только `min-width`, базовые стили пишутся для 360px:

```
sm 480 · md 768 · lg 1024 · xl 1280 · 2xl 1600
```

Заменяют прежние **одиннадцать** ad-hoc `max-width` (в которых `767` и `760`, `1040` и `1024`, `380` и `359` были дублями одной границы). CSS-переменные внутри `@media` не работают, поэтому значения зафиксированы комментарием в `tokens.css` как единственный разрешённый набор — любое другое число в `@media` считается ошибкой.

### 2.6. Слои и движение

`z-index` — только по шкале: `base 0 · raised 100 · sticky 200 · dropdown 300 · overlay 400 · modal 500 · toast 600`. Шаг 100 оставляет место для промежуточных слоёв без пересчёта.

Длительности: 80 / 140 / 200 / 280 ms. Дольше 250ms интерфейс ощущается вязким. При `prefers-reduced-motion: reduce` все четыре обнуляются на уровне токенов — то есть отключение анимаций работает во всём слое сразу, а не в каждом компоненте отдельно.

### 2.7. Плотность

Ключевое решение направления. Вместо двух дизайн-систем — одна с переключаемой плотностью:

```css
[data-density="compact"] {
  --density-card-padding: var(--space-16);  /* было 24 */
  --density-stack: var(--space-12);         /* было 16 */
  --density-row-y: var(--space-8);          /* было 12 */
  --control-height: 32px;                   /* было 40 */
}
```

Переопределяются **только семантические псевдонимы**, а не сама шкала. Атрибут вешается на любой контейнер — страницу, секцию, одну таблицу. Проверено в браузере: `padding` ячейки 12px → 8px.

Плотный режим предназначен для журнала оценок, панели управления, состава группы и конструктора курса. Студенческие страницы остаются в обычном.

## 3. Компоненты

Все классы имеют префикс `ui-`. Это не украшение: в проекте заняты имена `.card`, `.alert`, `.pagination`, `.empty-state`, `.avatar`, `.progress-*`. Префикс позволяет двум слоям сосуществовать и мигрировать страницы по одной.

**Правила слоя:** только токены; одна ответственность на класс; состояния через модификатор (`--primary`) или состояние (`.is-loading`, `.is-invalid`, `[disabled]`); никакого `!important`; вложенность не глубже двух уровней; отступы задаёт родитель через `gap`; минимальная цель для указателя 24×24px.

### 3.1. Кнопки

Пять вариантов вместо прежних шести несводимых: `--primary`, `--secondary`, `--ghost`, `--danger`, `--danger-quiet`. Размеры `--sm` / обычный / `--lg`, плюс `--block` и `--icon`.

**Главное изменение — кнопка больше не стилизуется селектором по тегу.** Прежнее правило `button { ... }` делало любой `<button>` синим primary автоматически; чтобы получить невыразительную кнопку, приходилось добавлять класс-перебивку. Теперь класс задаётся явно.

Полная таблица состояний:

| Состояние | Как задаётся | Что меняется |
|---|---|---|
| Обычное | `.ui-btn--primary` | Заливка `--color-primary` |
| Наведение | `:hover` | `--color-primary-hover` |
| Нажатие | `:active` | `--color-primary-active` |
| Фокус | `:focus-visible` | Кольцо 2px + отступ 2px, контраст ≥ 3:1 |
| Отключена | `[disabled]` / `[aria-disabled]` | Прозрачность 0.5, `not-allowed`, hover не срабатывает |
| Загрузка | `.is-loading` + `aria-busy` | Подпись скрывается, появляется спиннер, клики блокируются |

Загрузка сделана так, чтобы **кнопка не меняла ширину**: подпись остаётся в потоке (`visibility: hidden`), спиннер накладывается абсолютно. Прыгающая при отправке кнопка — распространённый дефект, которого здесь нет по конструкции.

`--danger` (красная заливка) предназначена только для случаев, где удаление и есть основное действие экрана — то есть для подтверждения в модалке. В остальных местах используется `--danger-quiet`, чтобы красная заливка не соревновалась за внимание с основным действием страницы.

### 3.2. Формы

`.ui-field` (обёртка) → `.ui-label` → `.ui-input` / `.ui-select` / `.ui-textarea` → `.ui-hint` → `.ui-error`.

**Состояние ошибки не существовало в проекте вообще** — ни `.errorlist`, ни `.field-error` в CSS не было. Теперь: красная граница, усиленное кольцо фокуса, сообщение с **иконкой** (не только цветом — требование WCAG 1.4.1 и NN/g).

**Сводка ошибок `.ui-error-summary`** по образцу GOV.UK: ставится в начало `<main>` выше `<h1>`, получает `role="alert"` и `tabindex="-1"` для программного фокуса, каждый пункт — ссылка на проблемное поле. Правило, которое легко нарушить: **текст в сводке и текст у поля обязаны совпадать дословно**.

**Валидация** (проверено в браузере): срабатывает на `blur`, но гаснет **сразу при исправлении ввода**, не дожидаясь повторного ухода с поля. Это прямое требование исследования Baymard — иначе пользователь считает, что его правка не сработала. Поле получает `aria-invalid` и связывается с сообщением через `aria-describedby`.

`.ui-check` — флажок или радио с областью нажатия ≥ 24px (WCAG 2.5.8), с состояниями checked и disabled через `:has()`.

### 3.3. Сообщения

Четыре уровня — `--info`, `--success`, `--warning`, `--danger` — с полным набором цветов у каждого.

Это закрывает п. 7.3 аудита: сейчас `base.html` рендерит все сообщения как `<p class="alert" role="status">`, игнорируя `message.tags`, из-за чего `messages.error()` визуально неотличим от `messages.success()`.

**Роли:** `role="status"` для обычных, `role="alert"` для ошибок. Прежний код ставил `status` всем, поэтому ошибка не объявлялась скринридером немедленно.

`.ui-toast-region` объявлена в разметке **заранее и всегда присутствует в DOM**. Если добавлять контейнер вместе с сообщением, скринридер ничего не объявит — живая область должна существовать до появления в ней текста.

### 3.4. Данные

**Карточки:** `.ui-card` с `__header` / `__title` / `__footer`, модификатор `--interactive` для кликабельных. `.ui-course-card` — специализация для каталога с обложкой 16:9 и `object-fit: cover`.

**Сетка `.ui-card-grid`** — одно правило `repeat(auto-fill, minmax(min(100%, 280px), 1fr))` на все каталоги. Конструкция `min(100%, 280px)` важна: без неё на экране уже 280px карточка вызовет горизонтальное переполнение.

**Таблицы:** `.ui-table-wrap` (прокрутка) + `.ui-table` со sticky-заголовком. `.ui-table__num` даёт выравнивание по правому краю и `tabular-nums` — без этого столбец процентов невозможно сравнивать взглядом.

**Прогресс — два вида.** Обычная полоса `.ui-progress` и **сегментированный `.ui-progress-segments`**: по сегменту на учебный блок, с состояниями `is-done` / `is-current`. Мотивация из Этапа 1: «62%» не отвечает на вопрос «сколько осталось и что дальше», а это главный вопрос на дашборде слушателя. Контейнер получает `role="img"` и текстовую сводку в `aria-label` — иначе для скринридера это шесть пустых элементов.

**Бейджи** получают точку перед подписью, поэтому статус читается формой и текстом, а не только цветом. Прежние `.status-pill` / `.status-pill.is-muted` («Активна» / «Отключена») различались исключительно цветом.

### 3.5. Модальное окно

Нативный `<dialog>` + `showModal()`. Он бесплатно даёт ловушку фокуса, закрытие по Escape и инертный фон — то, ради чего в React-мире подключают библиотеку.

Сверено с контрактом Radix Dialog и **проверено в браузере**:

| Требование | Статус |
|---|---|
| Фокус запирается внутри | ✓ (нативно) |
| Escape закрывает | ✓ проверено |
| Фокус возвращается на триггер | ✓ проверено |
| Заголовок связан через `aria-labelledby` | ✓ проверено |
| Фон инертен | ✓ (нативно) |

Заменяет `onclick="return confirm(...)"` в конструкторе курса. Нативный `confirm()` не стилизуется, блокирует поток и не показывает, **что именно** удаляется — новая модалка называет блок по имени и предупреждает о потере прогресса слушателей.

### 3.6. Состояния

`.ui-empty` — заголовок, пояснение, **действие**. Пустое состояние без действия считается недоделанным.

`.ui-skeleton` и `.ui-spinner`. Пороги (NN/g), они же критерий приёмки на Этапе 4:

| Длительность | Что показываем |
|---|---|
| менее 1 с | Ничего — индикатор только мешает |
| 1–10 с | Спиннер в кнопке или скелетон области |
| более 10 с | Прогресс с оценкой (импорт студентов из Excel) |

Скелетон применим **только** к области, подгружаемой отдельным запросом. Полностраничных скелетонов в server-rendered приложении быть не должно — страница приходит уже с данными. Анимация скелетона отключается при `prefers-reduced-motion` (NN/g отдельно предупреждает, что пульсация создаёт проблемы доступности).

### Найденный и исправленный баг слоя компонентов

При проверке на узком экране обнаружилось горизонтальное переполнение страницы. Причина оказалась не в разметке каталога, а **в самом компоненте таблицы**: у flex-потомка `min-width` по умолчанию равен `auto`, из-за чего широкая таблица не давала колонке сжаться и растягивала страницу — несмотря на то, что внутри уже был контейнер с `overflow-x: auto`.

Одного `min-width: 0` оказалось недостаточно — потребовалась пара `min-width: 0` + `max-width: 100%`. Это исправление ушло в `.ui-table-wrap`, `.ui-stack > *` и `.ui-cluster > *`, то есть баг починен в слое, а не на одной странице. Без браузерной проверки он ударил бы по каждой странице с таблицей внутри `.ui-stack` — то есть по журналу оценок и составу группы на Этапе 4.

Это ровно тот класс дефектов, который прежний код лечил глобальными заплатками `body { overflow-x: hidden }` — то есть скрытием симптома вместо устранения причины.

## 6. Правила для последующей работы

1. **Хардкод цвета или размера вне `tokens.css` — ошибка.** Значение либо становится токеном, либо использует существующий.
2. **`!important` запрещён.** Потребность в нём означает, что существующее правило специфичнее, чем задумано.
3. **`style=` в шаблоне разрешён в одном случае** — передача *данного* через кастомное свойство: `style="--progress: {{ percent }}%"`. Решение о внешнем виде остаётся в CSS, шаблон сообщает только число.
4. **Отступы принадлежат контейнеру** (`gap`), а не потомку (`margin`).
5. **`@media` — только пять значений** из `tokens.css`, только `min-width`.
6. **Цвет никогда не единственный носитель смысла** — дублируется формой, иконкой или текстом.
7. **Новый статический файл → `collectstatic`**, иначе падает всё приложение.
8. **Компонент не готов без состояний** hover / focus-visible / disabled / loading / error и без пустого состояния для списка.
