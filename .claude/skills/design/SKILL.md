# Дизайн-система МедЛМС

Проект переводится с самописного CSS на слой токенов и компонентов. Работа идёт постранично: два слоя сосуществуют, страницы мигрируют по одной. Состояние миграции — `docs/redesign/README.md`.

**Живой каталог компонентов: `/styleguide/`** (только для `is_staff`). Открой его перед тем, как делать новый компонент — скорее всего, нужный уже есть.

## Три слоя CSS, в порядке подключения

| Слой | Файлы | Правила |
|---|---|---|
| Токены | `static/css/base/tokens.css` | Единственный источник цвета, отступов, типографики, слоёв, длительностей |
| Компоненты | `static/css/components/ui.css`, `app-shell.css` | Всё с префиксом `ui-` (кроме оболочки). Переиспользуемое |
| Страница | `static/css/pages/*.css` | Подключается через `{% block extra_css %}`, только на своей странице |
| **Легаси** | `layouts/application.css`, `components/{card,forms,table,question-image}.css` | **Не расширять.** Удаляется по мере миграции страниц |

Если правило нужно двум страницам — оно в `components/ui.css`, а не скопировано в два `pages/*.css`.

## Незыблемые правила

1. **Хардкод цвета или размера вне `tokens.css` — ошибка.** Значение либо становится токеном, либо использует существующий.
2. **`!important` запрещён.** Потребность в нём означает, что существующее правило специфичнее, чем задумано, — упрощай его.
3. **`style=` в шаблоне разрешён ровно в одном случае** — передача *данного* через кастомное свойство: `style="--progress: {{ percent|floatformat:0 }}%"`. Решение о внешнем виде остаётся в CSS. См. ловушку про локаль ниже.
4. **Отступы принадлежат контейнеру** (`gap` на родителе), а не потомку (`margin`).
5. **`@media` — только пять значений** `min-width`, перечисленных в `tokens.css`: 480 / 768 / 1024 / 1280 / 1600. Базовые стили пишутся для 360px.
6. **Цвет никогда не единственный носитель смысла** — дублируй формой, иконкой или текстом.
7. **Мёртвый CSS удаляется в том же коммите**, где страница перестала им пользоваться, а не «потом».

## Как делать новую страницу

1. Открой `/styleguide/` и найди готовые компоненты.
2. Прочитай ближайший мигрированный аналог целиком (`templates/courses/catalog.html`, `templates/learning/course.html` — хорошие образцы).
3. Шапка страницы — `.page-head`, заголовок раздела — `.section-head`. Не изобретай седьмой вариант.
4. Повторяющаяся разметка — партиал в `templates/components/`, с комментарием-списком параметров в начале файла.
5. Всё передавай через `{% include ... with x=y %}`. Партиал не должен лезть во внешний контекст за переменной.
6. Если компоненту нужно что-то **вычислить** (сгруппировать, посчитать) — это `inclusion_tag`, а не логика во view. Примеры: `apps/ui/templatetags/form_tags.py`, `apps/learning/templatetags/learning_tags.py`.

## Формы

Никогда не выводи форму через `{{ form.as_p }}`. Только:

```django
{% load form_tags %}
{% form_errors form "Заголовок сводки" %}   {# в начале страницы, выше <h1> #}
{% form_field form.email autocomplete="email" %}
```

Тег сам проставляет класс виджета, `aria-describedby`, `aria-invalid` и разметку ошибки. Текст в сводке и у поля совпадает дословно по построению.

Формы без полей ввода (одна кнопка + hidden) не нуждаются ни в Django Form, ни в партиале — им нужна кнопка нужного класса и `data-submit-once`.

## Критерий приёмки страницы

Страница не готова, пока не выполнено **всё**:

**Раскладка** — 360 / 768 / 1280 / 1920 без горизонтального переполнения (проверяй `document.documentElement.scrollWidth === window.innerWidth`, а не на глаз); светлая и тёмная тема.

**Состояния** — пустое состояние с действием; ошибка (сводка + сообщение у поля); загрузка по порогам (<1с ничего, 1–10с спиннер, >10с прогресс); hover / focus-visible / disabled у всего интерактивного.

**Доступность** — логичный порядок Tab; один `<h1>` и без перескоков уровней; цель нажатия ≥ 24×24px; элемент в фокусе не скрыт липкой шапкой; `alt` у изображений; `aria-label` у иконочных кнопок.

**Код** — ни одного `style=` кроме передачи данного; ни одного `!important`; ни одного хардкоженного значения; мёртвый CSS удалён; **тексты сохранены дословно**.

**Проверки** — `manage.py check`, `pytest`, `ruff check`, `ruff format --check`; `collectstatic` при добавлении статики; страница открыта в браузере, консоль чиста.

## Сохранение текстов

Правило заказчика: существующие пользовательские строки не теряются и не переписываются. Перед коммитом сверяй машинно, а не глазами:

```bash
git show HEAD:templates/путь.html | grep -oE '>[^<>{%]{3,}<' | sed 's/^>//;s/<$//' | sort -u
```

Каждую строку из вывода проверь в новом шаблоне. На этом уже один раз поймал себя существующий тест.
